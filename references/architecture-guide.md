# Architecture Guide

> 供 `seo-architecture-expert` 执行审计时参考。

---

## 角色定位

验证网站的信息架构是否利于用户浏览和搜索引擎理解。清晰的架构帮助权重传递、帮助爬虫发现深层页面、提升用户体验。

---

## 评估维度

### 1. URL 结构

- 是否简洁、语义化（如 `/products/shoes` 而非 `/p?id=123&cat=5`）
- 是否统一使用小写和连字符（`-`）分隔
- 是否存在过多参数（`?key=value`）
- 是否包含无意义字符或 ID
- URL 长度是否适中（建议 < 75 字符）

### 2. URL 层级深度

- 重要页面距离首页的点击深度（建议 3 层以内，最多不超过 4 层）
- 深层页面（>4 层）是否有其他入口（如内链、Sitemap）
- 是否存在扁平化与层级化的平衡

### 3. 面包屑导航

- 是否存在面包屑导航（BreadcrumbList）
- 面包屑是否与 URL 层级一致
- 面包屑是否包含结构化数据标记
- 最后一个面包屑是否可点击（建议不可点击）

### 4. 内链架构

- 内链结构是否形成清晰的层级网络
- 重要页面是否获得足够的内链支持
- 内链分布是否均衡（避免某些页面过度链接）

### 5. 孤立页面检测

- 是否存在从首页出发无法通过链接到达的页面
- 孤立页面是否仅通过 Sitemap 被发现
- 是否存在内部搜索才能访问的页面

### 6. 锚文本质量

- 锚文本是否描述性（避免"点击这里"、"了解更多"）
- 同一页面的不同内链是否使用多样化锚文本
- 是否存在过度优化的锚文本（全部使用精确匹配关键词）

---

## 排名因素关联

- **内部链接结构**（Tier 2，第 7 位）：清晰的网站架构和合理的内链帮助传递权重，帮助爬虫发现页面
- **URL 长度与层级**（Tier 3）：短 URL、浅层级更利于用户和爬虫
- **内容格式**（Tier 3）：面包屑和层级结构提升可读性，有助于获取 Featured Snippet

---

## 评分指南

| 分数 | 等级 | 说明 |
|------|------|------|
| 90–100 | 优秀 | URL 简洁语义化、层级 ≤3 层、面包屑完整、无孤立页面、锚文本描述性 |
| 70–89 | 良好 | 轻微问题：部分 URL 参数过多、个别页面层级较深、少数锚文本不描述性 |
| 60–69 | 有风险 | URL 结构混乱、存在较深层级（>4 层）、有孤立页面、大量"点击这里"锚文本 |
| 0–59 | 严重 | URL 完全无意义、大量深层孤立页面、无面包屑、内链架构断裂 |
